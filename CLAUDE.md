# CLAUDE.md

NixOS and home-manager configuration for the desktop `yukiwari`. See `README.md` for the overview and layout.

## Editing

- This repository defines the machine: what is installed and where config files go. The config files themselves, Claude Code's included, live in the separate `dotfiles` repository (checked out at `~/!metier/dotfiles`), which `flake.nix` reads as the non-flake input `inputs.dotfiles`. Edit them there, not here.
- Most files under `~/.config`, `~/.claude` and similar are read-only links into the Nix store, pinned by `flake.lock`. After changing dotfiles, run `nix flake update dotfiles` here and rebuild. To try uncommitted dotfiles changes, add `--override-input dotfiles path:/home/alin/!metier/dotfiles` to the rebuild.
- The exceptions are linked straight to the dotfiles checkout with `liveDot` in `home/alin.nix` (the global `CLAUDE.md`, the `commit-message` skill, `keybindings.json`). Edits to them take effect without a rebuild; only adding or removing such a link needs one.
- The `writing-style` skill is not placed from here: its source is in dotfiles, and Claude Code gets it from claude.ai, synced to `~/.claude/skills/synced/`.
- Do not edit `hosts/desktop/hardware-configuration.nix`. It is generated by `nixos-generate-config`.
- The flake only sees files tracked by Git. jj tracks new files on its next snapshot, so run `jj st` before building after adding a file.

## Verifying

The Nix daemon is not reachable from Claude's sandbox, so builds cannot run there. Ask the user to run one of these:

- `nixos-rebuild build --flake .#yukiwari` to check that the system builds
- `sudo nixos-rebuild switch --flake .#yukiwari` to apply it

## Commits

Use Conventional Commits with a scope: `feat(desktop): ...`, `fix(kanata): ...`. Scopes in use: `desktop` (niri, waybar and other GUI pieces), `home` (`home/alin.nix` and CLI tools), `kanata`, `claude`, `flake`. Omit the scope for repository-wide changes such as `docs`.
