# CLAUDE.md

NixOS and home-manager configuration for the desktop `yukiwari`. See `README.md` for the overview and layout.

## Editing

- Most files under `~/.config`, `~/.claude` and similar are read-only links into the Nix store, placed by `home/alin.nix`. Edit the source under `dotfiles/` instead. Changes take effect only after a rebuild.
- The exceptions are linked straight to this checkout with `liveDot` in `home/alin.nix` (the global `CLAUDE.md`, the `commit-message` skill, `keybindings.json`). Edits to them under `dotfiles/` take effect without a rebuild; only adding or removing such a link needs one.
- This repository also manages Claude Code's own config (`dotfiles/claude/`): the global `CLAUDE.md`, `settings.json`, `managed-settings.json`, the `commit-message` skill and `writing-lint.nu`. The `writing-style` skill is not here: it is registered on claude.ai and synced to `~/.claude/skills/synced/`, and the Japanese version there is the source of truth. The rule names `writing-lint.nu` reports must match the section headings of that skill's `reference.md`.
- Do not edit `hosts/desktop/hardware-configuration.nix`. It is generated by `nixos-generate-config`.
- The flake only sees files tracked by Git. jj tracks new files on its next snapshot, so run `jj st` before building after adding a file.

## Verifying

The Nix daemon is not reachable from Claude's sandbox, so builds cannot run there. Ask the user to run one of these:

- `nixos-rebuild build --flake .#yukiwari` to check that the system builds
- `sudo nixos-rebuild switch --flake .#yukiwari` to apply it

## Commits

Use Conventional Commits with a scope: `feat(desktop): ...`, `fix(kanata): ...`. Scopes in use: `desktop` (niri, waybar and other GUI pieces), `home` (`home/alin.nix` and CLI tools), `kanata`, `claude`, `flake`. Omit the scope for repository-wide changes such as `docs`.
